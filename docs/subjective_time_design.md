# 体感時間設計 — 「精神と時の部屋」の時間拡張メカニズム検討

> **ステータス**: 検討段階（未実装）
> **対象**: 主に Recovery モード。Focus / Reflection への波及も記載。
> **作成日**: 2026-06-11

---

## 1. フレーミング — 体感時間は「モード別の設計軸」である

原作の精神と時の部屋は「外界の1日 = 部屋の1年」。本プロジェクトでこれに相当するのは
**実時間あたりの主観的滞在時間（体感時間）を操作すること** である。

重要なのは、モードによって望ましい方向が**逆**であること：

| モード | 望ましい体感時間 | 理由 |
|--------|----------------|------|
| **Recovery** | **拡張**（25分が1時間に感じる） | 短い実時間で「長く休んだ」感覚 → 回復感の最大化 |
| **Focus** | **圧縮**（2時間が30分に感じる） | フロー状態。時間を忘れるほど没入できている証拠 |
| **Reflection** | **定着**（体感の長さを記憶に固定） | 拡張された体感を振り返りで強化し、翌日以降も持続させる |

本ドキュメントは Recovery の「拡張」を中心に検討する。

---

## 2. 心理学的背景 — 体感時間が伸びる条件

時間知覚研究の主要な知見を、設計に使える形で整理する。

### 2.1 前向き時間評価と後向き時間評価は別物

- **前向き（prospective）** — 「今、時間が経つのが遅い/速い」。
  注意が時間そのものに向くと長く感じる。低覚醒・退屈・手持ち無沙汰で伸びる。
- **後向き（retrospective）** — 「振り返るとあの時間は長かった」。
  **形成された記憶の数（イベント密度・場面の切り替わり数）** に比例して伸びる。
  旅行の初日が長く感じるのはこれ。

→ Recovery では両方を狙えるが、**後向きの拡張が本命**。
「25分だったのに、すごく長く深く休んだ気がする」を作る。

### 2.2 設計に使える主要効果

| 効果 | 内容 | 代表的な研究系統 |
|------|------|----------------|
| **イベント分節化** | 場面の切り替わりが多いほど retrospective に長く感じる | Block & Zakay の記憶ベースモデル |
| **オッドボール効果** | 予期しない稀な刺激の瞬間は引き伸ばされて知覚される | Tse et al. (2004) |
| **畏怖（awe）** | 広大なものへの畏怖は「時間が豊富にある」感覚を生む | Rudd, Vohs & Aaker (2012) |
| **テンポ同調** | 遅いリズム（呼吸・音）への同調は内的時計を遅くする | Droit-Volet らの emotion–time 研究 |
| **時間手がかり除去** | 時計・通知がないと外的較正が効かず、主観時間が支配する | カジノ・洞窟実験の伝統 |
| **内受容感覚** | 呼吸・心拍への注意（マインドフルネス）は現在時間を引き伸ばす | Wittmann の interoception 研究 |
| **逆効果: フロー** | 没入課題は時間を圧縮する → Recovery では能動的課題を置かない | Csikszentmihalyi |

## 3. 具体メカニズム案（優先度順）

### M1: 圧縮昼夜サイクル — 「一晩眠った」環境証拠を与える ★最優先

**原理**: 脳は空の状態を経過時間の手がかり（zeitgeber）として使う。
25分の間に「深夜 → 月没 → 薄明 → 夜明け」を経験すると、
環境が「長い時間が経った」と語りかける。原作の部屋のトリックそのもの。

**実装**:
- Recovery シーンを 4 フェーズに分割（イベント分節化 M1×2.2 の合わせ技）:

  | フェーズ | 実時間配分 (25分時) | 環境変化 |
  |---------|-------------------|---------|
  | 深夜    | 0–10 分 | 満天の星、最暗 |
  | 月没    | 10–16 分 | 月が地平線へゆっくり沈む |
  | 薄明    | 16–22 分 | 地平線がわずかに青紫 `#1B3A4B` → `#2D4A6B` |
  | 夜明け前 | 22–25 分 | 東の空がほのかに暖色。終了の自然な合図を兼ねる |

- すべての遷移はクロスフェード ≥ 60 秒。**速い変化は仕様で禁止**（既存 Recovery 仕様準拠）。
- `duration_min` に対してフェーズ長を比例スケールする（20分でも30分でも4フェーズ）。

**実装先**: 新規 `TimeDilationDirector.cs`（RecoveryRoot 配下）。
フェーズタイムラインを保持し、Skybox マテリアルパラメータ・ライト色・
`AmbientAudioManager` のクリップを段階遷移させる。

**副次効果**: 夜明けフェーズが「そろそろ終わり」の非言語的予告になり、
突然の終了アラームが不要になる（M4 と接続）。

---

### M2: スパース・オッドボールイベント — 記憶のくさびを打つ

**原理**: 予期しない稀な出来事は (a) その瞬間の知覚時間を引き伸ばし、
(b) 独立した記憶チャンクとして残り retrospective 時間を伸ばす。

**実装**: セッション中 2〜4 回、ランダムタイミングで静かなイベントを発生させる。

- 流れ星（ゆっくり 3〜4 秒かけて流れる。閃光ではなくフェード）
- 湖面シーンなら: 遠くで魚が跳ねる波紋、蛍が一匹横切る
- 音響オッドボール: 遠くの梵鐘・水滴音が一度だけ鳴る

**制約**: Recovery 仕様の「速い動き禁止・通知禁止・受動性」を厳守。
イベントは**気づかなくてもよい強度**に抑える（視野の端、輝度上昇 +10% 以下、音量 -18dB 以下）。
ユーザーが「探す」行動を取らなくても、無意識下で記憶チャンクが形成されればよい。
発生間隔は固定にしない（予測可能になると oddball 効果が消える）。

**実装先**: `TimeDilationDirector.cs` 内のイベントスケジューラ +
小さな `OddballEvent.cs`（ParticleSystem / AudioClip をトリガー）。

---

### M3: 呼吸ガイドの漸減テンポ — 内的時計そのものを遅くする

**原理**: ユーザーが時間を「呼吸の回数」で無意識に数えるなら、
呼吸周期を徐々に遅くすれば同じ実時間に対する「内的なティック数」が減る。
さらに遅い呼吸は副交感神経優位 → 低覚醒 → 時間評価の歪みが増す。

**実装**: `BreathingGuide.cs` に漸減パラメータを追加。

```
開始時: 4-1-4-1 (10秒周期)  →  終盤: 5-2-5-2 (14秒周期)
セッション全体で線形に補間。変化率は知覚閾値以下（1分あたり +0.2 秒程度）
```

既存の `inhaleTime` 等を `AnimationCurve` 化するだけで対応可能。変更コストは最小。

---

### M4: 時間手がかりの完全遮断と「曖昧な終了」

**原理**: 外的時間情報がゼロなら、主観時間の歪みが較正されずそのまま残る。

**実装**:
- Recovery 中は時計・残り時間・進捗バーを一切出さない（現仕様で達成済み — 維持を明文化）。
- **終了を「アラーム」にしない**: M1 の夜明けフェーズ → 環境光のゆっくりした上昇 →
  AI の一言、という連続的なフェードで終わる。急な終了は「もう25分？」と
  実時間への再較正を強制してしまう。
- EXIT ボタンは維持（ユーザー主権）。ただし視野の端に置き、常時注意を引かない。

**実装先**: `RecoveryMode.cs` の終了シーケンスに `EndingFadeCoroutine` を追加。

---

### M5: 広大さ・awe 演出 — 「時間が豊富にある」感覚

**原理**: Rudd らの研究では、畏怖を感じた被験者は「時間が十分にある」と
報告する傾向が高まった。VR は awe 誘発に極めて有利なメディア。

**実装**:
- 星空の**奥行き**を強調: 星を単一スカイボックスでなく 2〜3 層のパララックスに分け、
  頭を動かしたとき微妙な視差で「無限の奥行き」を感じさせる。
- 視野の下方にも空間を広げる（崖の上・湖面に星が映る等、足元方向の広がり）。
- 1 フェーズに一度だけ、淡い天の川や星雲がゆっくり視認可能になる。

**コスト**: シェーダ・アート工数が大きい。v0.2 以降の段階導入を推奨。

---

### M6: 音響テンポの漸減と間隔漸増ベル

**原理**: M3 の音響版。環境音のテンポ・密度をセッション後半に向けて下げる。
また一定でない間隔のベル（例: 4分 → 5分 → 6.5分）は間隔評価を狂わせる。

**実装**: `AmbientAudioManager.cs` に `tempoEnvelope: AnimationCurve` を追加。
雨音なら粒密度、波音なら周期を後半 10〜15% 遅くする（知覚閾値以下で）。

---

### M7: Reflection での記憶アンカリング — 拡張を定着させる

**原理**: retrospective 時間は想起時に再構成される。セッション直後に
「何が起きたか」を事実として述べると、分節化された記憶（M1 のフェーズ、M2 のイベント）が
固定され、「長かった」という評価が持続する。

**実装**:
- セッション終了時の AI フィードバックに事実の肯定文を 1 つ含める（質問形式は使わない）:
  ✗ 「流れ星に気づきましたか？」（× 回答を期待する質問）
  ○ 「セッション中、流れ星が 1 つ流れました」（○ 受動的想起の補助）
- backend 側: `TimeDilationDirector` が発生イベントのリストを
  `/recovery/end` リクエストに同梱 → `MockProvider.end_feedback()` が
  そこから 1 件選んで肯定文で述べる。
- **「部屋内時間」演出の削除**: 「体感換算」表示は、ユーザーに
  「正しく感じたか？」の自己評価を促してしまうため削除。
  体感時間の計測は暗黙的手法（後述セクション 4.1）に切り替える。

## 4. 計測と検証 — 効いているかをデータで確かめる

体感時間は主観だが、**ユーザーに尋ねずに測定できる**。

### 4.1 暗黙的計測手法（受動性を守る）

Recovery の原則「行動を促さない」を守るため、明示的な質問（「何分に感じましたか？」）は行わない。
代わりに以下の暗黙的指標を記録する：

| 指標 | 取得方法 | 体感時間との相関仮説 |
|------|---------|-------------------|
| **余韻時間** | セッション終了（夜明けフェード完了）から EXIT ボタン押下までの秒数 | 長く休んだと感じたほど余韻に浸る時間が長い（要検証） |
| **頭部運動量** | セッション中の HMD 加速度積分値（VR プラットフォーム API 経由） | 動きが少ないほど鎮静 → 時間知覚が鈍化（Wittmann らの研究より） |
| **呼吸同期率** | `BreathingGuide` の拡縮と実際の呼吸（胸部センサー将来対応）の位相差 | 同調度が高いほど内受容感覚優位 → 時間拡張 |

`SessionSummary` に追加するフィールド（`schemas.py` 拡張時）:

```jsonc
{
  "session_summary": {
    // ... 既存フィールド ...
    "afterglow_seconds": 18.3,      // 余韻時間
    "head_motion_total": 0.42,      // 正規化済み頭部運動量（0=完全静止, 1=通常会話レベル）
    "time_dilation_index": 0.73     // 複合指標（後述の式で算出、0〜1、高いほど拡張成功）
  }
}
```

**`time_dilation_index` 算出式** (暫定):
```
TDI = 0.4 × normalize(afterglow) + 0.4 × (1 - head_motion) + 0.2 × breathing_sync
```
係数は A/B テスト後に最適化する。

> **注意（CLAUDE.md 規約）**: 実装時は `schemas.py` と `docs/recovery_mode_spec.md` の
> 両方を更新し、`pytest` を通すこと。

### 4.2 検証プロトコル

1. **ベースライン収集**: メカニズム未導入の現行 Recovery で 10〜20 セッション分の
   `time_dilation_index` を記録。
2. **A/B 導入**: メカニズムを 1 つずつオンにして比較（`session_config` に
   有効メカニズムのフラグを記録するフィールドを追加）。
3. **相関分析**: `time_dilation_index` × `efficiency_score` の関係を見る。
   仮説: **体感時間の拡張は回復感（fatigue_delta）と正の相関を持つ**。
   もし相関がなければ、体感拡張は独立の価値指標として扱う。
4. **反証**: もし `time_dilation_index` が高いのに `fatigue_delta` が悪化するメカニズムがあれば、
   それは**削除**する（例: オッドボールの刺激が強すぎて覚醒を上げた場合）。

**外部基準との照合**（将来）:
ユーザーが自発的に「今日の休息は深かった」等をメモとして残した場合、
そのセッションの `time_dilation_index` が高いか確認する（事後分析）。

## 6. リスクと設計上の倫理

| リスク | 対策 |
|--------|------|
| **ユーザーに行動を促すことによる休息阻害** | セッション中・終了時ともに質問・入力要求を一切しない。計測は暗黙的手法のみ（余韻時間・頭部運動量） |
| 環境変化による VR 酔い | すべての遷移を 60 秒以上のフェードに制限。カメラは不動（既存仕様） |
| オッドボールが覚醒を上げ回復を阻害 | 強度上限を定義（輝度 +10%、音量 -18dB 以下、視野の端）。気づかなくてもよい強度。A/B で fatigue_delta が悪化したら無効化 |
| 「時間操作されている」不信感 | 仕組みを隠さない。設定画面で各メカニズムを個別オフ可能にする |
| AI の想起文が「正解」を期待させる | 質問形式を禁止。事実の肯定文（「流れ星が流れました」）のみ使う |
| 長期使用による効果減衰（慣れ） | オッドボールの種類プール制・フェーズ構成のバリエーション（星空/湖/雪原） |

---

## 7. 結論（要約）

1. 体感時間は **Recovery=拡張 / Focus=圧縮 / Reflection=定着** のモード別設計軸として扱う。
2. 拡張の本命は **retrospective 記憶密度**: 圧縮昼夜サイクル（M1）による
   イベント分節化が最も費用対効果が高い。
3. ただし**最初に実装すべきは計測**（P1: 暗黙的指標 `afterglow_seconds` / 
   `head_motion_total` / `time_dilation_index`）。効果が測れない演出は積まない。
4. すべてのメカニズムは Recovery の既存原則（**速い動き禁止・通知禁止・受動性維持**・低彩度）の
   内側で動く。ユーザーに行動を促すことで回復を犠牲にした時間演出は本末転倒。
